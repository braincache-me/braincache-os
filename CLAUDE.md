## Product naming — "ClipVault" vs "BrainCache"

The codebase, Xcode scheme, target, and `project.yml` are all named **`ClipVault`**, but the shipping product is **`BrainCache`** (`PRODUCT_NAME: BrainCache`, bundle ID `com.TalkFlow.BrainCache`). Source folders, types, and the test suite use `ClipVault`; user-facing strings, the menu-bar app, the CLI binary, and the app's own hard-excluded bundle ID use `BrainCache`. Treat the two names as the same app.

### Repository layout (top-level components)

The repo contains four build artifacts plus tooling:

- **`ClipVault/ClipVault/`** — the macOS app (AppKit, no SwiftUI). Subsystems: `Monitor/` (clipboard capture), `Storage/` (GRDB), `Services/AI/` (classification, embeddings, RAG, agentic search), `Services/ActivityCapture/` (activity recorder), `Services/WritingAssistant/`, `Services/VoiceTranscription/`, and `UI/` (panels per feature). See per-subsystem patterns below.
- **`ClipVault/BrainCacheCLI/`** — a separate target that builds the `braincache` ArgumentParser CLI (subcommands `clips`, `audio`, `activity`, `info`). It is **read-only**, reads the on-disk SQLite DB and activity-log folder directly (the app need not be running), and is embedded into the app bundle at `Contents/Resources/braincache` via a build phase. Vector search / `ask` need an OpenAI key (Keychain or `OPENAI_API_KEY`). Full reference in `ClipVault/docs/CLI.md`.
- **`braincache_server/`** — a local Node.js + React console (no runtime npm deps) for B2B/enterprise review of Activity Capture logs. `cd braincache_server && npm start` → `http://127.0.0.1:8787`; `npm test` runs `node --test`. Loads daily JSONL logs, clusters them into tasks, and drafts agent skills from repeatable workflows.
- **`ClipVault/scripts/`** — `dev-run.sh` (build + launch an **isolated dev variant**: separate bundle ID `com.TalkFlow.BrainCache.dev`, separate Application Support / UserDefaults suite via `BuildVariant.swift`, so dev and prod don't clobber each other's TCC permissions or data; Keychain is intentionally shared), `build-dmg.sh`, `notarize.sh`, `deploy-braincache.sh`, `install-sparkle-tools.sh`, `reset-and-test.sh`, `smoke-test.sh`.

### Voice transcription

`Services/VoiceTranscription/` drives live dictation: `VoiceTranscriptionRecorder` captures audio, one realtime WebSocket per source (mic + optional system audio) streams to `RealtimeTranscriptionClient` / `RealtimeTranslationClient`, and `VoiceTranscriptionService` (a `shared` singleton) surfaces partial/final transcripts. `FinalizeIntent` decides what happens to the result: `.paste`, `.skipPaste` (hand to AI window), or `.rewriteAndPaste` (LLM grammar cleanup, falling back to raw transcript on failure so dictation is never lost).

### Voice panel — "Save recording" media file + crash-safe transcript drafts

**Save recording checkbox** (top-left of the voice panel) writes the live session to disk via `Services/VoiceTranscription/VoiceMediaRecorder` — independent of the realtime transcription sockets (own `AVAudioEngine` mic tap with the panel's selected device, own ScreenCaptureKit streams). Recording starts the moment the checkbox is ticked (or, if ticked while idle, the moment the next session starts — `mediaRecordingArmed`) and unticking finalises the file. Files land in `Settings.voiceRecordingsFolderURL` (default `~/Movies/BrainCache Recordings`, `… (Dev)` for the dev variant; override with `voiceRecordingsFolderPath`). The folder glyph next to the checkbox reveals the live file / the folder in Finder.

- No window attached → `.m4a` (AAC 48 kHz stereo, mic + system audio when the Sys toggle is on; the file follows Sys toggles mid-session via `setIncludesSystemAudio`).
- Window attached via 📎 → `.mov` (H.264 ≤ 1920 px long edge, 15 fps, + audio) of that window (`SCContentFilter(desktopIndependentWindow:)`). While the file is being written the 📎 source is **locked**: `attachWindowTapped` shows `attachLockedMessage` instead of the picker. The pure state machine is `UI/VoicePanel/VoiceMediaRecordingPolicy`.
- **Crash safety**: `AVAssetWriter.movieFragmentInterval = 10 s` — verified empirically that both `.m4a` and `.mov` stay playable up to the last fragment after an abrupt kill. Real-time inputs drop a buffer rather than block when the encoder lags. A 1 s **video heartbeat** re-appends the last frame so a static window doesn't leave the video track shorter than the audio (and every fragment stays continuous).
- **Window closed**: two independent signals — `SCStreamDelegate.didStopWithError` and a 2 s `CGWindowListCopyWindowInfo` watchdog — funnel into `handleSourceLost`, which finalises the file first, then fires `onSourceLost`. The service reports `MediaStopReason.sourceLost`; the panel shows a warning banner and `MeetingPromptBubbleController.showMediaSourceLost(appName:saved:)` drops the menu-bar bubble ("Stop & Save" / "Keep going"). Transcription keeps running — only the file stops.
- A `.file` clip pointing at the recording is inserted **at start** (so it is in history even after a crash) and deleted only if the recording ends with nothing to keep (< 1 s / never received media). The media recorder is always stopped with the session (`stopAndTranscribe`, `cancel`, `abortPreservingTranscript`, app termination).

**Crash-safe transcript drafts** (`TranscriptDraftPersister`): during `.recording` the service flushes `transcript.combined` (including in-flight partials) every `VoiceTranscriptionService.draftFlushInterval` (5 s) into a single clip — first flush inserts, later flushes call `ClipStore.updateTextContent(id:text:resetAIProcessing:)` on the same row (FTS `clips_au` trigger keeps search in sync). Also flushed on `willSleep`, `willPowerOff`, and `NSApplication.willTerminate`. The final save (`saveTranscriptClip`) reuses the draft clip with `isFinal: true`, which resets `ai_processed` so the pipeline re-indexes the finished text — history never shows a duplicate. `cancel()` is only reached from error-recovery paths, so it folds partials into the draft instead of discarding them. Tests in `VoiceMediaRecordingTests.swift`.

### Meeting detection (macOS 14+)

`Services/MeetingDetection/` watches for other apps capturing the microphone and offers to record the meeting via a menu-bar bubble (`UI/MeetingPrompt/MeetingPromptBubbleController`). Pipeline: `MicUsageMonitor` (CoreAudio `kAudioHardwarePropertyProcessObjectList` + per-process `kAudioProcessPropertyIsRunningInput`, listener + 2 s poll fallback, no TCC permission needed for metadata) → `MeetingAppClassifier` (pure, unit-tested: bundle-ID prefixes → meetingApp/browser/ignored; browser window-title matching incl. the Meet code regex `[a-z]{3}-[a-z]{4}-[a-z]{3}`) → `BrowserWindowTitleReader` (AX titles, reuses the existing Accessibility grant) → `MeetingDetector` (2.5 s debounce, 10 s session-end grace, one prompt per mic session, snooze via Settings; while a browser holds the mic without a verified meeting title — Chromium only exposes the frontmost tab's title per window — the title check retries every `browserRecheckSeconds` (10 s) instead of giving up for the session). Chrome mic use surfaces as `com.google.Chrome.helper`; Safari as `com.apple.WebKit.GPU` (shared by all WebKit hosts — the Safari window-title scan disambiguates). The bubble's Record button calls `VoiceRecordingPanelController.startRecording(forcingSystemAudio: true)`; `effectiveFinalizeIntent` forces `.skipPaste` for system-audio captures, so the transcript is saved as a clip, never pasted into the call. When the meeting ends (mic released) while BrainCache is still recording with system audio and the voice panel is hidden, the bubble reappears in stop-suggestion mode ("Stop & Save" / "Keep going", gated by `MeetingPromptPolicy.shouldSuggestStop`) — Stop & Save shows the panel and finalizes. If the status item is hidden (crowded menu bar on a small screen, or parked under the notch — detected via `MeetingPromptBubbleController.anchorIsVisible`: occlusion state + auxiliary top areas), the bubble falls back to the top-right corner of the main screen so the offer still shows. Do not use window-alpha animator fade-in on the bubble panel — the animation can silently never fire, leaving the panel stuck at alpha 0; alpha is set directly. Settings: `meetingDetectionEnabled` (default true, checkbox in Preferences → General), `meetingPromptSnoozeUntil`, `meetingPromptSnoozeMinutes` (default 60). Tests in `MeetingDetectionTests.swift`.

## Non-obvious patterns

### DispatchSourceTimer usage

`ClipboardMonitor` and `PurgeScheduler` both use `DispatchSourceTimer` from a private serial queue. Key rules:

- Always call `timer.cancel()` before nilling out the reference; never call `cancel()` on an already-suspended timer without resuming first, or you'll crash.
- The monitor suspends/resumes the timer on `NSWorkspace.willSleepNotification` / `didWakeNotification` using an `isSuspended` flag to guard double-suspend.
- Transient clipboard debounce: instead of emitting immediately on each change-count tick, a `DispatchWorkItem` is scheduled 100 ms out and cancelled if a new change arrives, preventing duplicate entries for apps that write multiple pasteboard types in rapid succession.

### GRDB migration pattern

All schema changes go through `DatabaseMigrator` in `DatabaseManager.migrate()`. Add a new `migrator.registerMigration("v2") { ... }` block; never modify the existing `"v1"` block.

Tests use `DatabaseManager().setupInMemory()` to get an in-memory `DatabaseQueue` — do not call `DatabaseManager.shared` in tests.

### FTS5 sync triggers

Three SQL triggers (`clips_ai`, `clips_ad`, `clips_au`) keep the `clips_fts` virtual table in sync with the `clips` table. The insert trigger checks `is_indexed = 1` so large pastes (>10 MB) with `is_indexed = 0` are stored but never added to the FTS index.

If you add columns to `clips`, check whether the triggers need updating.

### Pasteboard type handling

`PasteboardReader` checks for `org.nspasteboard.ConcealedType` first and returns `nil` immediately — this skips password manager entries. Priority order for reading: concealed check → HTML → RTF → string → PNG → TIFF image → file URLs. HTML is checked before plain text because HTML is the richer format and most apps that write HTML also write a plain-text fallback — capturing HTML gives better round-trip fidelity.

### Search ranking

`ClipStore.search` uses an FTS5 MATCH query with a recency blend:

```sql
ORDER BY rank * exp(-0.001 * (unixepoch() - created_at))
```

This means a slightly less relevant but very recent clip can outscore a perfect match from six months ago. Tune the `0.001` decay constant if users find old results surfacing too much or too little.

### AppKit-only, no SwiftUI

All UI is AppKit. Do not add SwiftUI views. The search panel is an `NSPanel` (not `NSWindow`) so it can be non-activating and float above other windows.

### Panel show/hide performance

`SearchPanelController` pre-creates the window at launch and only calls `orderOut` / `makeKeyAndOrderFront` — never re-creates the window. This keeps panel appearance under 50 ms.

### CGEvent-based paste

`PasteService` writes content to `NSPasteboard.general` then synthesises a Cmd+V `CGEvent` targeting the previously frontmost app (captured by `AppDetector` before the panel appears). This requires Accessibility permission — on first launch after onboarding, `AccessibilityChecker.requestAccess()` is called when permission is not yet granted (see the AccessibilityChecker section below).

### AccessibilityChecker — macOS-version-conditional URL and guarded alert

`openAccessibilitySettings()` uses a version-conditional URL because the path changed in macOS 13 (Ventura):
- macOS 13+: `x-apple.systempreferences:com.apple.settings.PrivacySecurity.extension?Privacy_Accessibility`
- macOS 12 and earlier: `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`

On macOS 13+, `kAXTrustedCheckOptionPrompt = true` no longer shows a system dialog — calling `AXIsProcessTrustedWithOptions` with the prompt flag is still done first (for backward compatibility), but the app must open System Settings itself via the URL above.

For the non-onboarding path (existing users who already completed onboarding), `AppDelegate.finishInitialLaunch` shows an `NSAlert` before opening System Settings, so users understand why the settings page appeared. The alert logic is extracted into `AccessibilityOnboardingAlert` for testability. The alert is only shown when `!AccessibilityChecker.isGranted`.

For the onboarding path, `OnboardingWindowController.show()` defers `showWindow(nil)`, `makeKeyAndOrderFront`, and `NSApp.activate` to the next run loop iteration via `DispatchQueue.main.async` — this is required for `LSUIElement = true` apps where `setActivationPolicy(.regular)` is not synchronous from the window server's perspective. `renderCurrentStep()`, `window?.center()`, and the policy change itself remain synchronous.

### Settings

All user-facing preferences are stored in `UserDefaults` via `Settings.swift`. Keys are string constants defined there. Do not access `UserDefaults` directly elsewhere.

### Pinned clips

Pinned clips are ordered first in both `fetchRecent` and `search` (`ORDER BY is_pinned DESC, ...`). They are also excluded from all purge queries (`WHERE is_pinned = 0`).

### OpenAI integration — feature gating

All AI features (classification, embedding, RAG chat) are gated behind `Settings.isAIEnabled`, which returns `!Settings.openAIAPIKey.isEmpty`. No API calls are ever made without an explicit key. The `OpenAIClient` shared instance reads the key at call time so key rotation takes effect immediately.

### OpenAI client retry / backoff

`OpenAIClient` retries on 429 and 5xx responses with exponential backoff: 1 s → 2 s → 4 s, max 3 retries. On 401 (bad key) it does NOT retry — it throws `OpenAIError.unauthorized` immediately and the pipeline surfaces this in the AI Preferences tab. Network errors pause the pipeline; it resumes on `didWakeNotification`.

### AI indexing pipeline ordering

`AIIndexingPipeline` processes clips in exactly this order for each clip: classify → (describe if image) → embed. The pipeline runs on a serial `OperationQueue` with `.utility` QoS and `maxConcurrentOperationCount = 1`. It pauses on `NSWorkspace.willSleepNotification` and resumes on `didWakeNotification` (same pattern as `ClipboardMonitor`). State is one of `.idle`, `.processing(clipId:, progress:)`, `.paused`, `.error(String)`.

### Heuristic pre-tagging

`ContentClassifier` short-circuits the LLM for obvious patterns: URLs, email addresses, file paths, and JSON/XML blobs are tagged heuristically without an API call — saves ~20% of classification costs. The LLM is still called for everything that doesn't match a heuristic.

### Embedding storage format

Embeddings are stored as raw `Float32` BLOBs in the `clip_embeddings` table (`clip_id INTEGER PRIMARY KEY, embedding BLOB, model TEXT, dimensions INTEGER`). 256 dimensions × 4 bytes = 1,024 bytes per clip. Encode/decode with `Data(bytes:count:)` / `withUnsafeBytes`. Cascade delete is declared on `clip_id` so deleting a clip also removes its embedding.

### sqlite-vector integration (deferred)

The plan is to use the sqlite-vector extension (v0.9.95) for SIMD-accelerated vector search, but Apple's system SQLite has `SQLITE_OMIT_LOAD_EXTENSION` set, so a custom SQLite build is required (see [GRDBCustomSQLiteBuild](https://github.com/SwiftedMind/GRDBCustomSQLiteBuild)). Until that manual build step is done, `EmbeddingStore.findNearest(to:topK:)` performs exact brute-force cosine similarity in Swift and `quantize()` / `preloadQuantized()` are no-ops. When the extension is linked, register it via `sqlite3_auto_extension` before any GRDB connection opens, and call `vector_init('clip_embeddings', 'embedding', 'type=FLOAT32,dimension=256,distance=COSINE')` in `DatabaseManager.prepareDatabase` (per-connection requirement).

### Quantization lifecycle

After any bulk insert (backfill) or bulk delete (purge), call `EmbeddingStore.quantize()` to rebuild the quantization index. Then call `EmbeddingStore.preloadQuantized()` to keep quantized vectors in memory for fast approximate search. `PurgeScheduler` has a post-purge hook for this. When the sqlite-vector extension is not linked, both methods are no-ops and exact cosine search is used instead.

### FTS5 now indexes two columns

Since migration `"v4"`, the `clips_fts` virtual table is defined as:

```sql
CREATE VIRTUAL TABLE clips_fts USING fts5(text_content, image_description, content='clips', content_rowid='id')
```

Both columns are synced by the three triggers (`clips_ai`, `clips_ad`, `clips_au`). If you add more columns to `clips` that should be searchable, update the FTS virtual table definition and all three triggers.

### Migration v4 schema additions

Migration `"v4"` adds to the `clips` table:
- `tags TEXT` — JSON-encoded string array of LLM-assigned tags, nullable
- `image_description TEXT` — vision LLM description for image clips, nullable
- `ai_processed INTEGER NOT NULL DEFAULT 0` — 0 = unprocessed, 1 = processed, 2 = failed
- `ai_processed_at DOUBLE` — Unix timestamp of last AI processing attempt, nullable

And creates the `clip_embeddings` table:
- `clip_id INTEGER PRIMARY KEY REFERENCES clips(id) ON DELETE CASCADE`
- `embedding BLOB NOT NULL`
- `model TEXT NOT NULL DEFAULT 'text-embedding-3-small'`
- `dimensions INTEGER NOT NULL DEFAULT 256`

### Hybrid search

When AI is enabled, `VectorSearchEngine.hybridSearch(query:topK:)` merges FTS5 results (from `ClipStore.search`) and vector results (from `EmbeddingStore.findNearest`) using Reciprocal Rank Fusion with k=60: `score = Σ 1/(60 + rank_i)`. The search panel uses hybrid search when AI is enabled and falls back to FTS5-only when AI is disabled or no embeddings exist.

### Chat history schema — migration v5

Migration `"v5"` adds two tables:

`conversations`:
- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `title TEXT NOT NULL` — auto-generated from first user message, truncated to 60 chars
- `created_at DOUBLE NOT NULL`, `updated_at DOUBLE NOT NULL` — Unix timestamps; `updated_at` is bumped on every new message

`chat_messages`:
- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `conversation_id INTEGER NOT NULL REFERENCES conversations(id) ON DELETE CASCADE` — cascade delete removes all messages when conversation is deleted
- `role TEXT NOT NULL` — "user" or "assistant"
- `content TEXT NOT NULL`
- `cited_clip_ids TEXT` — JSON-encoded `[Int64]`, nullable (assistant messages only)
- `created_at DOUBLE NOT NULL`

Index: `idx_chat_messages_conv ON chat_messages(conversation_id, created_at)`.

All CRUD is in `ConversationStore`. The `ChatMessage` struct (in `ChatBubbleView.swift`) has optional `id: Int64?` and `conversationId: Int64?` for DB round-tripping; the in-memory initialiser remains backward-compatible.

### Conversation context window

When `ChatPanelController.sendMessage` fires, it fetches the current conversation's messages from `ConversationStore`, converts them to `[OpenAIClient.ChatMessage]`, and passes them to `RAGEngine.query(_:conversationHistory:)`. Inside `RAGEngine`, the messages array is ordered:

1. System prompt
2. RAG context as a system message
3. Prior conversation history (last `Settings.shared.chatContextMessageLimit` messages, default 20)
4. Current user question

If the accumulated token estimate (chars / 4) approaches the model's context limit, history messages are dropped first, then RAG context is trimmed. This prevents silent truncation by the API.

### Agentic RAG — tool-use loop

`AgenticRAGEngine` wraps the classic RAG flow with an autonomous search loop. When `Settings.shared.agenticSearchEnabled` is true, it replaces `RAGEngine` in `ChatPanelController`.

Tool definitions live in `SearchToolDefinitions.swift` as OpenAI function-calling schemas:
- `search_by_keyword` — FTS5 full-text search via `ClipStore.search`
- `search_by_semantic` — vector similarity via `VectorSearchEngine`
- `filter_by_app` — `ClipStore.fetchByApp(appName:limit:)`
- `filter_by_date_range` — `ClipStore.fetchByDateRange(start:end:limit:)`
- `filter_by_tags` — `ClipStore.fetchByTags(tags:matchAll:limit:)`
- `filter_by_content_type` — `ClipStore.fetchByContentType(contentType:limit:)`

Execution loop (max `Settings.shared.agenticMaxIterations` rounds, default 3):
1. Send system prompt + conversation history + tools to `OpenAIClient.chatCompletion(tools:toolChoice:)`.
2. If response contains `tool_calls`: execute each call via `executeToolCall`, format results (clip ID, first 200 chars, source app, date), append as tool response messages, continue loop.
3. If response is plain text: return it as the final answer.
4. If the iteration cap is reached while the model is still calling tools: send a final "provide your answer now" message with `tool_choice: "none"`.

If `agenticSearchEnabled` is false, `AgenticRAGEngine` falls back to `RAGEngine.query` (classic single-shot RAG).

The chat panel shows a "Searching…" status indicator during tool-call iterations. After the final answer, the assistant bubble includes a collapsible "Search steps" summary showing which tools were called and result counts.

### Ask AI — Responses API streaming, thinking traces, and tools

Ask AI (voice panel → AI Assist window) streams through `OpenAIClient.streamResponse` — the **Responses API** (`POST /v1/responses`) — not Chat Completions, because it is the only surface that streams reasoning summaries and hosts the built-in `web_search` tool. Everything else (RAG chat, classification, rewrite) stays on Chat Completions.

- `ResponsesStreamParser` (own file, pure/testable) maps SSE JSON payloads to `ResponsesStreamEvent`: `.reasoningDelta` (`response.reasoning_summary_text.delta`), `.textDelta`, `.webSearchStarted`, `.functionCall`, `.completed(responseId:usage:)`, `.failed`.
- Reasoning summaries are requested via `reasoning: {effort, summary: "auto"}` (effort comes from `Settings.reasoningEffort`, same gating as before). Some models/orgs reject `summary` — on a 400 naming it, the request retries once without the summary field so the answer still streams.
- `AIAssistEntry.thinking` accumulates the trace; `AIAssistWindowController.thinkingBlock` renders it as a raw-HTML `<details>` block above the answer (open while the answer is empty, collapsed once tokens arrive). marked.js passes raw block HTML through unsanitised, so the text is escaped in Swift and newlines become `<br>`.
- Local function tools run in a bounded loop (max 4 rounds): collected `function_call` items are executed, then the next round continues via `previous_response_id` with `function_call_output` items as the only input.

Tools are per-flag opt-in in Preferences → AI ("Ask AI Tools" section), assembled by `AskAIToolDefinitions.tools(...)` (Responses-API *flat* function schema — no nested `"function"` wrapper like `SearchToolDefinitions`):

| Settings key (default false) | Tools registered |
|---|---|
| `askAIWebSearchEnabled` | hosted `{"type": "web_search"}` — for latest info / quick research |
| `claudeCodeHistoryToolEnabled` | `search_claude_code_history` + `ask_claude_code` |
| `codexHistoryToolEnabled` | `search_codex_history` + `ask_codex` |

`search_*` tools grep the local JSONL transcripts (`~/.claude`, `~/.codex`) via `AgentHistorySearchService` (injectable roots; the app is **not** sandboxed so the dot-folders are readable). `ask_*` tools run the installed CLI through `AgentCLIBridge`: `claude -p --continue --model opus --effort low "<q>"` / `codex exec resume --last --sandbox read-only --skip-git-repo-check "<q>"` — argument-array exec (no shell, no injection), 120 s timeout, cwd = optional `project_path`. Per-tool guidance strings live in `Prompts.json` under `askAI.*` and are appended to the system prompt only for enabled tools.

The AI Preferences tab exposes all of these across four sections: API Key, Model Selection (4 popup buttons + refresh), Chat Configuration (steppers/sliders), and Agentic Search. ### Chat panel UX

`ChatPanelWindow` is a resizable `.nonactivatingPanel` with `.resizable` in its style mask, `minSize` of 520×380, and `isMovableByWindowBackground = true`. The window preserves its size across show/hide cycles.

`ChatBubbleView` renders assistant messages with markdown formatting via `MarkdownRenderer` (fenced code blocks, inline code, bold, italic, headers, lists, blockquotes, links). User messages are plain text. Every bubble has a small copy icon (doc.on.doc) in the top-right corner that copies the raw message text to clipboard with visual feedback (turns green briefly).

Clicking a clip badge (#ID) in an assistant message shows an `NSPopover` with the full clip content (header with ID/app/date, tags, scrollable content, "Copy Full Content" button) instead of navigating away from the chat.

Each conversation row in the sidebar shows a delete button (xmark.circle.fill) on mouse hover, in addition to the right-click context menu (Rename / Delete). The `ActionTarget` helper class (in `ChatBubbleView.swift`) is module-internal so it can be reused in `ConversationListView` and `ChatPanelController`.

### Copy/paste fix — performKeyEquivalent in panel subclasses

`ChatPanelWindow` and `SearchPanelWindow` are `NSPanel` subclasses. Standard Edit menu key equivalents (Cmd+C/V/X/A/Z) can be swallowed by the panel before reaching the focused text field. The fix is a `performKeyEquivalent(_:)` override that calls `super.performKeyEquivalent(event)` for these keys before any custom handling, letting the responder chain reach the text field naturally. The `AppDelegate`'s Edit menu items must target `nil` (first responder) — not a specific object — for this chain to work.

### Activity Recorder — architecture and service entry points

All activity-capture code lives under two new folders:
- `ClipVault/Services/ActivityCapture/` — capture pipeline, event model, storage
- `ClipVault/UI/ActivityHistory/` — history window, sidebar, timeline views

The main coordinator is `ActivityCaptureCoordinator`. It is instantiated in `AppDelegate` and owns the full capture lifecycle:
- `start()` / `pause()` / `resume()` / `stop()` manage `NSEvent` global monitors and the `ActivityFocusObserver`
- Click events call `ActivityElementInspector` (via `ActivityAXInspecting` protocol) to resolve AX attributes at the click position
- Key events are recorded only as shortcut summaries (`⌘C`, `⌃⌥⌘T`) — raw text keystrokes are never stored
- Secure text fields never have their `controlValue` recorded (role/name only)
- BrainCache's own bundle ID and apps in `activityCaptureExcludedBundleIDs` are silently skipped
- Screenshot capture is driven by `WindowScreenshotService` (injectable via `WindowScreenshotCapturing` protocol) and gated by `ScreenshotCapturePolicy`
- The coordinator suspends its periodic timer on `NSWorkspace.willSleepNotification` and restarts on `didWakeNotification` (same pattern as `ClipboardMonitor`)

### Activity Recorder — security-scoped log-root behavior

BrainCache is sandboxed. Writing to a user-visible folder under Documents requires the user to explicitly grant access via `NSOpenPanel`. The flow:
1. `ActivityCaptureFolderAccess.promptUserToChooseFolder()` runs an `NSOpenPanel` the first time Activity Capture is enabled
2. A security-scoped bookmark is written to `Settings.activityCaptureLogRootBookmark`
3. On subsequent launches, `ActivityCaptureFolderAccess.resolveAccess()` restores the bookmark before the recorder starts
4. `logsURL` and `screenshotsURL` are derived from the resolved root; the directory structure is created if missing
5. Stale bookmarks are automatically refreshed if the folder is still accessible

The entitlement is `com.apple.security.files.user-selected.read-write` (upgraded from read-only).

### Activity Recorder — JSONL/screenshot folder layout

```
<chosen root>/
  logs/
    YYYY-MM-DD.jsonl           # one event per line, ISO 8601 ms-precision timestamps
  screenshots/
    YYYY-MM-DD/
      YYYY-MM-DDThh-mm-ss-mmm_AppName_trigger.jpg
  summaries/
    YYYY-MM-DD.json            # daily summary: event count, app list, storage size
```

`ActivityLogWriter` appends to the day's JSONL file on a serial utility queue with buffered flushes (every 25 events or every 2 seconds). It rotates files at local calendar midnight. `ActivityDaySummary` maintains the `.summary.json` file so the History sidebar can show counts and storage sizes without reparsing all JSONL.

### Activity Recorder — privacy / redaction rules

- Secure text fields (`kAXSecureTextFieldRole`): `controlValue` is always `nil`; role and name are still recorded
- Key events: only keyboard shortcuts with ⌘/⌃/⌥/Fn modifier are stored, never plain text keystrokes
- BrainCache's own bundle ID is hard-excluded — the app never records its own interactions
- Apps in `activityCaptureExcludedBundleIDs` are silently skipped for both events and screenshots
- If Screen Recording permission is absent, screenshot capture is disabled and marked unavailable; metadata logging continues

### Activity Recorder — menu bar and Preferences sync pattern

The source of truth for on/off and capture settings is `Settings.swift`. Components stay in sync via `NotificationCenter`:
- `activityCaptureEnabledDidChange` — toggling capture on/off
- `activityCapturePausedDidChange` — pause / resume
- `activityCaptureSettingsDidChange` — any screenshot/quality/interval setting
- `activityCaptureLogRootDidChange` — folder bookmark updated
- `activityCaptureExclusionsDidChange` — excluded bundle ID list changed

`StatusMenuBuilder` and `GeneralPrefsView` both observe these notifications to refresh their UI. The menu bar icon shows a green badge overlay while recording and no badge while inactive or paused.

### Writing Assistant — architecture

All Writing Assistant code lives under `Services/WritingAssistant/` and `UI/WritingAssistant/`, with `WritingPrefsView` in `UI/Preferences/`. It is gated behind an OpenAI API key and provides a focused-field companion panel:

- **Writing Assistant panel** — opens from double-tap right Command (`WritingAssistantHotkeyMonitor`) or the legacy rewrite entry point (`WritingAssistantCoordinator.handleRewriteHotkey()`). The old immediate AI rewrite path now opens the panel instead of rewriting immediately. If the focused element is editable, `FocusedTextReader` snapshots its current value/selection and the panel appears near the caret or selection.
- **Prompt input** — the panel focuses its input as soon as it opens. Return submits. Cmd-Return submits while no result exists, then becomes Replace after generation. Escape closes the panel even when the text field has focus. The panel also has an xmark close button.
- **Generated result actions** — after generation, the panel shows Replace `⌘↩`, Append `⌘↓`, and Copy `⌘C` buttons with the hotkeys inline. Replace writes through the same clipboard-paste path as rewrite; Append moves to the end of the selected range before pasting; Copy leaves the generated text on the pasteboard and suppresses clipboard recapture.

`WritingAssistantCoordinator` is owned by `AppDelegate` (a plain stored property). It owns `FocusedTextReader`, `TextRewriteService`, `WritingAssistantHotkeyMonitor`, and `WritingAssistantPanelController`; `AppDelegate` starts/stops the hotkey monitor during launch/termination.

### Writing Assistant — focused-element reading

`FocusedTextReader` (conforms to `FocusedTextReading`) reads the system-wide `kAXFocusedUIElementAttribute` and returns a `FocusedTextSnapshot` — a plain-data struct (role, value, selection, secure/editable flags, pid) kept separate from the live `AXUIElement` so the disambiguation logic (`hasRewritableText`, `hasSelection`, `textToRewrite`) is unit-testable. Secure roles (`AXSecureTextField`, `AXPasswordField`) never have their value read. `caretRect(for:caretLocation:textLength:)` resolves caret geometry via the `kAXBoundsForRangeParameterizedAttribute` parameterized attribute (zero-length range first, last-character fallback) for placing the rewrite HUD; it returns nil for apps that don't expose it, and HUD placement falls back to the mouse location.

When the frontmost app is in `FocusedTextReader.browserBundleIDs`, `AXManualAccessibility` is set on it **before** the primary system-wide query (not just in the fallback) so Chromium's lazily-built tree is awake — this is the AX-only browser fix.

### Writing Assistant — text insertion and undo

**Replace** writes text via clipboard paste (⌘A first for whole-field, the existing selection for a partial rewrite) so it lands as a single undoable edit — ⌘Z restores the original in one step. `KeystrokeSynthesizer` synthesises the ⌘A / ⌘V `CGEvent`s. The inserted text is left on the clipboard and `ClipboardMonitor.suppressNextCapture(hash:)` stops it being re-captured (same pattern as voice rewrite). `WritingAssistantHUD` still shows transient rewrite progress/success when the direct rewrite path is used internally.

**Append** writes plain text to the pasteboard, activates the source app by pid, and pastes after a short activation delay. If the source had a selection, `KeystrokeSynthesizer.moveRight(pid:)` collapses the selection to its trailing edge before paste.

### Writing Assistant — panel UI

`WritingAssistantPanelController` uses a borderless `.nonactivatingPanel` (`WritingAssistantPanelWindow`) with a fixed compact size so it does not jump between generated/loading states. The panel content is a clear root view with a separately clipped `NSVisualEffectView` material subview; keep this wrapper structure to avoid square corner artifacts around the rounded blur surface. Use `WritingAssistantLoaderView` for the three-dot loading state so the panel matches the rewrite HUD.

### Writing Assistant — Settings keys and prompts

| Key | Default | Notes |
|---|---|---|
| `writingRewritePrompt` | bundled | Editable; empty falls back to default at read time |
| `writingRewriteModel` | `chatModel` | Model for rewrites |

The default rewrite/panel system prompt lives in `Prompts.json` under `writingAssistant` (`rewriteSystem`). `TextRewriteService` reads both settings live at call time, so they post no notification.

For the panel flow, `TextRewriteService.generateAssistantResponse` sends:
1. system: `Settings.shared.writingRewritePrompt`
2. user: `assistantUserPrompt(instruction:sourceText:snapshot:)`

The user prompt includes the typed instruction, app name, window title, AX role, source kind, and `CURRENT FOCUSED INPUT` from `snapshot.textToRewrite`. It also tells the model that terminal/shell command requests should return only the command, no explanation or markdown.

AX↔AppKit coordinate conversion goes through `AXGeometry.cocoaRect(fromAXRect:)` (a vertical flip about the primary screen height).
